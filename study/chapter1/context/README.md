# 实验 1-1：上下文的关键作用

## 实验目的

本实验复现《深入理解 AI Agent》第一章的上下文消融实验，观察历史消息、保留的推理过程、工具定义和工具执行结果分别被移除后，对 Agent 完成多步骤任务的影响。

## 实验过程

### 1. DeepSeek 冒烟测试

先执行以下命令检查 API 连接、基础对话和工具调用是否正常：

```powershell
python tests/manual/check_deepseek.py
```

结果为 `4/4 tests passed`，四项检查（模型配置、基础对话、计算器工具、货币换算工具）均通过。

### 2. 正式消融实验

执行命令：

```powershell
python run_experiment_1_1.py --provider deepseek --output-dir validation\deepseek_run_01
```

实验使用受约束（`guarded`）任务：将 Q2 的 210 万欧元、Q3 的 180 万英镑和 Q4 的 3.8 亿日元换算为美元，再与 Q1 的 250 万美元相加，计算全年总收入与季度平均收入。提示词要求模型不得自行估计汇率，必须依据工具观测结果。

本次使用五种上下文模式：

| 模式 | 被移除的上下文 |
| --- | --- |
| `full` | 无，完整上下文基线 |
| `no_history` | 历史消息 |
| `no_reasoning` | 写回历史的 `reasoning_content` |
| `no_tool_calls` | 工具定义 |
| `no_tool_results` | 工具执行结果（以空内容静默隐藏） |

## 实验结果

### 汇总

| 上下文模式 | outcome | 是否完成 | 任务正确 | 迭代次数 | 工具调用 | 重复调用 | 最终表现 |
| --- | --- | --- | --- | ---: | ---: | --- | --- |
| `full` | `correct` | 是 | 是 | 3 | 4 | 否 | 成功得到正确总额与平均值 |
| `no_history` | `no_terminal_response` | 否 | 否 | 5 | 15 | 是 | 重复进行相同换汇，达到迭代上限 |
| `no_reasoning` | `correct` | 是 | 是 | 4 | 5 | 否 | 仍完成任务，但比基线多一轮和一次工具调用 |
| `no_tool_calls` | `no_unsupported_numbers` | 是 | 否 | 1 | 0 | 否 | 未编造汇率或金额，只输出了文本形式的工具调用请求 |
| `no_tool_results` | `no_terminal_response` | 否 | 否 | 5 | 8 | 是 | 多次得到空工具结果后反复重试，达到迭代上限 |

完整上下文基线组的最终答案为：

```text
Annual total = $9,602,895.73
Quarterly average = $2,400,723.93
```

基线组先调用三次 `convert_currency`，再调用一次 `code_interpreter` 完成求和与平均值计算，因此在 3 轮内完成了任务。

### 各组行为分析

#### `full`：完整上下文

完整上下文组正确保存了此前的工具调用和工具结果。模型先取得三种货币换算结果，再用代码解释器汇总计算，最终在 3 轮、4 次工具调用后完成任务。这是本实验的基线。

#### `no_history`：移除历史消息

该组每轮只保留系统提示与原始任务，模型无法看到自己先前已经完成过的换算。因此它持续重复 EUR、GBP、JPY 到 USD 的三次换算：5 轮共调用 15 次工具，最终触及迭代上限而没有给出答案。该结果说明历史上下文对于避免重复操作、维持多步骤任务连续性十分关键。

#### `no_reasoning`：移除已保留的推理过程

该组仍然得到正确的总额和平均值，但用了 4 轮和 5 次工具调用。需要谨慎解释：这里移除的是写回历史的 `reasoning_content`，模型在每一个新回合仍可重新进行推理，并且可继续读取工具结果。对于本次结构固定、步骤明确的任务，工具观测已足以支持下一步决策，因此没有观察到明显的正确性退化。

这不表示推理过程没有价值，而是说明在本模型、本任务和本次运行中，实验没有验证“移除已保留推理一定会导致性能下降”的强结论。

#### `no_tool_calls`：移除工具定义

该组的请求没有携带工具定义，因此模型实际无法发起工具调用，记录为 0 次工具调用。模型没有自行编造汇率、总额或平均值，而是输出了文本形式的工具调用请求；所以它虽然有终止响应，却没有完成任务。

“没有工具调用”本身是该消融设置的必然结果。更有意义的观察是：在提示词要求不得估算汇率的约束下，模型没有用未经观测支持的数字伪造一个看似完整的答案。

#### `no_tool_results`：移除工具执行结果

该组仍保留工具定义，模型也实际调用了工具，但每个工具结果在发送回模型时都被置为空。模型无法知道换算结果，先重复原有换算，随后以单笔换汇和其他工具继续探测；5 轮累计 8 次工具调用，仍无法完成任务。

该现象体现了工具结果的反馈作用：只有“能调用工具”并不够，Agent 还必须能将观察到的结果纳入后续决策，否则会进入无反馈的重复执行。

## 学习心得

1. **上下文不是单一概念。** 历史消息、推理记录、工具定义和工具结果承担的功能不同，移除其中一项会造成不同类型的失败。
2. **工具结果是闭环的核心。** 本次 `no_tool_results` 组表明，Agent 若看不到外部环境反馈，就无法把“行动”转化为可靠结论，甚至会反复调用同一个工具。
3. **历史消息提升效率与连贯性。** `no_history` 的 15 次工具调用与基线的 4 次形成鲜明对比；模型不是不会使用工具，而是遗忘了先前已经做过的工作。
4. **需要区分“完成”和“正确”。** `no_tool_calls` 组有终止响应，但没有有效答案；因此评价 Agent 时不能只看是否停止，还要检查任务是否正确完成及其数字是否有观测依据。
5. **单次运行不应被过度概括。** 本次 `no_reasoning` 组依旧正确，说明消融效应会受到模型、任务难度和随机性的影响。更稳妥的结论应来自同一配置下的多次重复实验，并报告每组的完成率、正确率及平均工具调用次数。
