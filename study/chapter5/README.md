**状态：学习中。** 已完成实验 5-1 的离线机制测试，并保留了真实 API 鉴权失败结果。

## 核心概念

Chapter 5 讨论 Coding Agent 的执行循环、故障恢复与代码作为工具的能力。跨厂商接管实验强调：Agent 轨迹不应直接绑定某一家 API 格式，而应使用中立结构保存消息、工具调用、工具结果以及可移植的推理内容。

不同厂商会在思考块或工具调用上附加专属签名。工具名称与参数可以重新渲染，厂商凭证却不能直接迁移。因此跨厂商恢复需要区分“可读语义”和“协议凭证”，并为目标厂商不接受历史原生工具调用的情况准备文本化降级路径。

## 阶段性理解

1. 跨厂商迁移的主要难点不是文本，而是各家专属的思考签名和工具调用协议。
2. 中立轨迹可以降低存储格式与单一厂商 API 的耦合。
3. 故障恢复需要可审计的边界：区分注入的源厂商故障和目标厂商真实返回的格式错误。
4. 凭据、网络和模型可用性属于实验前置门槛；前置失败也应保存，而不是误判为模型或接管算法失败。
