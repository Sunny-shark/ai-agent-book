# 第 2 章学习档案：上下文工程

## 学习目标

- 理解模型 API 中消息、工具定义和工具结果如何共同构成 Agent 的当前上下文。
- 理解稳定前缀、动态状态与 KV Cache 命中之间的关系。
- 掌握提示工程、Agent Skills 和上下文压缩在 Agent Harness 中的作用。

## 阅读与概念笔记

- **上下文是 Agent 的工作记忆。** 系统提示、用户任务、历史消息、工具 schema 和工具结果都必须被组织进当前请求；没有写回上下文的观察不会被模型自动记住。
- **稳定前缀是缓存边界。** 固定系统提示、工具定义和不变范例应放在请求前部；用户输入、状态栏和工具结果等频繁变化的信息应置后，避免让前缀缓存整体失效。
- **压缩与隔离是两种不同手段。** 摘要和事实提取降低单会话的 token 占用；相互独立的子任务则应使用隔离上下文，减少无关历史的干扰。
- **提示工程属于上下文工程。** 规则的结构、工具描述、few-shot 示例和提示注入边界，决定模型如何解释上下文及如何选择工具。

## 本章总结

### 学到的内容

- 上下文工程不只是“写好提示词”，还包括让模型可靠地接收工具反馈、维护可复用状态并控制推理成本。
- KV Cache 的收益要通过匹配的 hit/miss 对照与 TTFT 测量验证，不能只依据一次回答速度判断。
