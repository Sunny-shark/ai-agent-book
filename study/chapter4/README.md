# 第 4 章学习档案

**状态：学习中。** 已完成主动工具发现的离线机制自检，并部分跑通本地 Qwen3-4B + 真实 MCP 工具 campaign。

## 核心概念

Chapter 4 关注 Agent 如何感知和作用于外部环境。工具不仅是可调用的函数，也包含名称、描述、参数 schema、返回结果和执行约束；这些信息会进入上下文并影响模型的选择质量与推理成本。

当工具目录扩大到上百项时，常见的全量注入方式会让每轮请求重复携带大量无关 schema。主动工具发现只保留少量基础工具和 `discover_tools`，由 Agent 在遇到能力缺口时描述需求，再通过语义检索加载少量专用工具。这种方式的主要价值是控制上下文成本，并缩小当前步骤的候选范围。

## 阶段性理解

1. 工具描述会占用上下文窗口，因此工具管理本身属于上下文工程。
2. 检索预筛选只根据初始问题选择一次工具，容易漏掉多步骤任务后期出现的新能力需求。
3. 主动发现把检索时机推迟到能力缺口真正出现时，更适合跨领域、多阶段 Agent。
4. 评估工具 Agent 不能只看“选中了什么”，还要验证真实回执、产物、完成状态和失败原因。
